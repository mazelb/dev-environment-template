## Plan: Add OAuth Authentication with MFA and RBAC to RAG & API Archetypes

Add OAuth 2.0 authentication (Google, GitHub) with hybrid session management (short-lived JWT + Redis refresh tokens), TOTP-based MFA as optional second factor, role-based access control (RBAC) with granular permissions, and AWS Secrets Manager integration with runtime rotation support to both `rag-project` and `api-service` archetypes.

### Further Considerations

1. **OAuth token refresh for API calls**: Should we store encrypted OAuth provider access tokens and implement background refresh jobs to maintain long-term access for calling provider APIs on behalf of users (e.g., accessing Google Drive, GitHub repos)? This would require `BackgroundTask` or Celery jobs for token refresh before expiration.

2. **Audit logging granularity**: Should audit logs include all CRUD operations on sensitive resources (users, roles, documents), or only authentication events and permission checks? Should logs be stored in database with retention policy, or shipped to CloudWatch/ELK stack? Do you need real-time audit event webhooks for SIEM integration?

3. **Social login without account creation**: Should OAuth allow automatic user account creation on first login, or require manual account provisioning first with OAuth linking after? Should we support account merging when same email used across providers? What's the user lifecycle for OAuth-only accounts (no password)?
